# 2026-09-22｜关键架构定稿日

[返回项目目录](低空消防无人机工程日志.md)

**硬件角色：**

- `[已确认]` 当前载板为 **JETSON-IO-BASE-A Rev2**；它只是**载板**，不是处理器。计算核心是其上的 **Jetson Nano 模组**，具体模组配置及 RAM 尚不明确。
- `[已确认]` Jetson Nano 侧运行 Ubuntu、ROS、相机/雷达处理及任务逻辑；**独立飞控板上的 PX4**负责实时飞行控制，两者通过 MAVROS/MAVLink 通信。
- `[待确认]` 学长提及 Nano 和 TF/microSD 卡的读写方式，但不能将存储介质当作已验证的实时信号接口；须以实际板卡和接线为准。

**视觉路线切换：**

- `[已确认的设计选择]` 学长担忧当前 Nano 算力不足以满足此前的 YOLO 方案，决定当前主线改为 **SSD-MobileNetV2 + TensorRT**。
- `[已确认的目标流程]` 采集图像 → 标注数据 → 训练/验证 SSD-MobileNetV2 → TensorRT 优化 → Jetson Nano 运行推理 → ROS 发布识别结果。
- `[历史方案]` YOLOv5/v8n、改造 YOLO 骨干网络等旧措辞只用于解释早期记录；**此刻不得当成最终架构**。路线确定并不代表模型已训练、部署或完成性能测试。

**地图与定位分阶段：**

- `[已确认的设计选择]` **提前手动飞行**获取场景数据，使用 **LiDAR + Cartographer 建图**，保存地图；比赛或后续运行阶段使用**已有二维地图 + AMCL 定位**，避免重复进行完整建图。
- `[技术边界]` AMCL 主要提供二维平面位姿 `x、y、yaw`，**不能单独解决三维位置、姿态或无人机完整状态估计**。`z、roll、pitch` 来源、里程计与融合方案尚未明确。
- `[技术边界]` 从 Cartographer 迁到 AMCL 不是替换一个包名：必须核查占据栅格地图、激光与里程计输入、初始位姿、`map/odom/base_link` TF、时间同步与适用的传感器几何条件。

**整机架构与重要限制：**

- `[已确认]` **PX4 ↔ MAVROS/MAVLink ↔ Jetson Nano**；Nano 的 ROS 承担 Camera→SSD-MobileNetV2/TensorRT、LiDAR→AMCL 以及任务决策。Gazebo + PX4 SITL 作为先行仿真路径。
- `[技术边界]` 图像检测框只回答“图像中有什么、大致在哪个像素区域”，**不直接等于目标世界坐标**；相机标定、深度或额外几何约束尚未落实。
- `[技术边界]` “ROS 经 MAVROS 向 PX4 发送飞行设定值”和“外部定位结果输入 PX4 的估计融合接口”是**不同链路**；MAVROS 连通不能证明定位已闭环。
- `[待确认]` Ubuntu/ROS/PX4/Gazebo/JetPack/TensorRT 具体版本、坐标系约定、外部定位融合方式、目标空间定位方式。
