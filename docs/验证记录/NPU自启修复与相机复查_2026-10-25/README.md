原上电脚本已经能发现可变化的编号，失败来自rk_npu_autostart.py及rk_npu_boot.sh固定3-1.1／30101。修复在独立分支codex/npu-usb-autostart-20261025完成：

- 新增[rk_npu_usb.py](../../../tools/rk_npu_usb.py)，根据真实sysfs路径核对fe900000.dwc3控制器、直属05e3:0610／0616集线器及固定1号下游端口；要求全系统恰好一个2207设备，核对busnum／devpath及180a／0019产品ID。总线数字可变，物理位置与唯一性仍固定。
- [启动程序](../../../tools/rk_npu_autostart.py)使用上述物理识别结果，接受不同总线上的已核实启动态；仍验证上电资源归属、真实序列号和内部系统就绪，不自动复位或无限重试。
- [固件helper](../../../tools/rk_npu_boot.sh)保留升级工具SHA256、官方Git提交／四个固件blob及板型校验。sysfs与厂商工具均要求唯一目标，再从实际设备行取得LocationID并在本次传输各阶段锁定；不猜厂商编号编码，不删除位置保护。每阶段重新核对设备、模式与位置。
- 原GPIO／电源脚本及systemd units保持原字节，仍是电源→固件→代理依赖链。主系统分区、内核、DTB、飞控参数与模型未修改。

正式副本位于/usr/local/lib/shell-rk-npu，root所有0644；原日常helper路径/home/jcfh/npu_runtime_175同步安装boot／usb／power三个依赖文件。修改前的已安装脚本保存在/home/jcfh/npu_runtime_175/autostart_install/usbfix_before_20261025，原件副本也收入证据归档，未删除回退备份。
