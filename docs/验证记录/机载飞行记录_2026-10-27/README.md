## 3. 方法与预先判据

在当天日志§16先写入判据，再读最终结果。每轮至少预热至六项readiness持续有效15秒，然后记录90秒正式窗口。两组都运行相同ROS观察器、`top -b -d 2`与`vmstat 1`，另保留逐秒`/proc`采样。

- 主对照次序：关→完整开→完整开→关；完整开为优化后的2FPS场景存档，另记录每次推理源帧。
- SHELL追问性能是否值得后，追加两轮无图像核心记录。
- 开启组相对关闭组：整机CPU均值增加≤5个百分点、可用内存下降≤150MiB、iowait P99≤5%；关键话题频率下降≤5%，控制定时器间隔P99增加≤5ms且最大间隔≤100ms；健康比例≥99%，无新增推理过期或录包溢出。

5个百分点等为本轮保守工程筛查预算，不是PX4官方飞行放行标准。CPU为全部在线核归一化的整机占用，进程100%则表示一个核。结果含两组共同存在的测量工具开销，不是无观察工具时的飞行裸负载。

首轮原程序试测因观察脚本对同一话题混用AnyMsg与String而无效，保留失败原文并修正后重测。最初图像版会激活15FPS预览编码，测得90.65% CPU；修正为独立2FPS存档后再进行两轮正式比较，该探索轮不混入最终平均值。
