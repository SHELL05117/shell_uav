## 3. 发现与边界

### 3.1 NPU启动失败：USB总线编号被固定

启动约5.56秒，原电源服务已成功发现板内NPU，实际节点为`1-1.1 / 2207:180a`。约5.76秒，固件服务报`Unexpected NPU boot USB state: {'1-1.1': '2207:180a'}`并退出1，代理因依赖失败未启动。当前sysfs确认NPU位于fe900000.dwc3下05e3集线器的1号端口。

已部署rk_npu_autostart.py与rk_npu_boot.sh的SHA256均与上一轮源码一致；前者仅接受旧`3-1.1`，后者也固定`3-1.1`、父集线器路径及`LocationID=30101`。**已确认的本次阻塞是软件将可变化的USB总线编号作为固定身份。** 尚未执行本次固件传输或推理，不能由此认定NPU芯片损坏，也不能提前保证解除路径限制后所有后续阶段正常。

后续应在独立功能分支修正身份识别，保留板内物理控制器／集线器／端口、厂商产品ID、唯一目标和固件哈希保护，复验启动、推理及冷启动；不能简单删除保护或仅替换一次总线数字。本轮按检查范围保留失败现场，没有修改或重启NPU服务。10月24日的一次重启通过保留为历史事实，不能覆盖本次失败。
