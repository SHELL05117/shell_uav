## 1. 板端建立USB网卡

正常启动Ubuntu，保持配套12V供电，用数据线连接板端Type-C OTG和电脑。电脑PowerShell复制脚本，密码只在终端输入：

```powershell
scp "D:\SHELL\uav1018\tools\rk_usb_ssh.sh" jcfh@172.20.10.4:~/rk_usb_ssh.sh
```

在现有Wi-Fi SSH终端运行：

```bash
sudo bash ~/rk_usb_ssh.sh
```

脚本创建shell_usb_ssh gadget及单一RNDIS功能，配置Windows OS描述符，绑定fe800000.dwc3，将对应USB网卡设为192.168.77.1/24。只操作此gadget和USB地址；现有控制器被其他configfs gadget占用则停止，不解绑其他设备。若出错，保留第一条错误，不继续电脑地址步骤。执行成功不等于Windows已枚举成功。

## 2. Windows设置USB地址并连接

等待Windows识别新USB网卡。以管理员身份打开PowerShell，按脚本固定的USB主机MAC精确选择接口：

```powershell
$rkUsb = @(Get-NetAdapter | Where-Object MacAddress -eq '02-53-48-45-4C-02')
if ($rkUsb.Count -ne 1) { throw '未找到唯一的RK USB网卡，先检查数据线和Windows驱动识别结果。' }
if (-not (Get-NetIPAddress -InterfaceIndex $rkUsb[0].ifIndex -AddressFamily IPv4 -IPAddress '192.168.77.2' -ErrorAction SilentlyContinue)) {
    New-NetIPAddress -InterfaceIndex $rkUsb[0].ifIndex -IPAddress '192.168.77.2' -PrefixLength 24
}
ssh jcfh@192.168.77.1
```

此处192.168.77.0/24是本次新规划的直连网段，若电脑已经使用该网段，先协调改为另一个空闲网段并同步两端地址。Windows只给目标USB接口添加静态IPv4，不设置网关／DNS，互联网继续走Wi-Fi。FinalShell新建SSH连接也可使用192.168.77.1、22端口、jcfh及现有账户密码。

若Windows未找到USB网卡，先提供板端脚本输出和设备管理器新设备名称／状态／硬件ID，区分未枚举与驱动匹配失败；仅在设备明确属于本次RNDIS功能时考虑系统自带RNDIS驱动，不强行把其他USB设备绑定成网卡。Windows是否自动安装成功须实际确认。

## 3. 本次有效期及回查

当前为本次开机临时配置，重启后需重新执行板端脚本；不会自动安装开机服务。先验收USB SSH，再按需求固化启动。USB线拔插通常保留本次配置，实际恢复以输出为准。

通过现有Wi-Fi终端停止本脚本的USB功能：

```bash
sudo bash ~/rk_usb_ssh.sh stop
```

该命令删除本脚本的USB地址、停用对应接口并解绑自己的gadget，保留configfs结构便于再次start。若启动中途失败且接口未注册，stop跳过接口操作、仍尝试解绑自己的gadget。不要对configfs属性使用rm -rf。

| 现象 | 优先回查 |
| --- | --- |
| 创建rndis或写OS描述符失败 | 第一条脚本错误、实际BSP属性／功能支持 |
| 写UDC失败或Device busy | 其他gadget／驱动是否占用控制器，不强制解绑 |
| 板端USB接口已出现、电脑无网卡 | Type-C数据连接及Windows设备枚举／驱动 |
| Windows已设置地址但SSH超时 | USB接口链路、两端地址与网段冲突 |
| SSH connection refused | 板端22监听；与USB枚举阶段分别处理 |

## 4. USB SSH成功后配置开机自启

**SHELL已确认USB连接成功。** 以下复用成功的板端~/rk_usb_ssh.sh，安装[开机服务文件](../../tools/rk-usb-ssh.service)，不修改USB地址或设备标识。服务文件设置oneshot、启动顺序及硬件等待；已按[systemd237源码](https://raw.githubusercontent.com/systemd/systemd/v237/src/core/service.c)核对，旧版oneshot不能使用非no的Restart，故不添加自动重试指令。实际服务加载及重启恢复仍须由板端结果确认。

电脑PowerShell复制服务文件，经已经连通的USB网络：

```powershell
scp "D:\SHELL\uav1018\tools\rk-usb-ssh.service" jcfh@192.168.77.1:~/rk-usb-ssh.service
```

在板端SSH终端执行：

```bash
sudo install -m 0755 ~/rk_usb_ssh.sh /usr/local/sbin/rk_usb_ssh.sh
sudo install -m 0644 ~/rk-usb-ssh.service /etc/systemd/system/rk-usb-ssh.service
sudo systemctl daemon-reload
sudo systemctl enable ssh
sudo systemctl enable --now rk-usb-ssh.service
sudo systemctl status rk-usb-ssh.service --no-pager -l
```

以上首轮enable --now调用脚本start，已绑定时仅确认USB接口地址和UP状态；不主动stop／restart当前USB链路。若此前已经由本服务管理且需要修改配置，应改由Wi-Fi或本地终端执行restart，避免USB会话中途断开。

成功状态为enabled及active (exited)，表示启动脚本完成并保留USB配置；该程序无需一直运行。服务等待UDC注册，启动超时设为30秒；超时或脚本失败时按日志处理，再从Wi-Fi或本地终端启动服务。configfs挂载失败则优先查依赖挂载单元，不把所有失败都归于Wi-Fi。Windows原来的192.168.77.2通常随同一设备身份保留，不重复创建地址。

当前安装任务结束、可以重启时在板端执行：

```bash
sudo reboot
```

USB会话随重启断开；系统启动后从电脑重新执行：

```powershell
ssh jcfh@192.168.77.1
```

能在重启后无需手动运行脚本而登录，才记为开机恢复通过。若连接不上，使用Wi-Fi SSH或板载终端查看：

```bash
sudo journalctl -b -u rk-usb-ssh.service --no-pager -n 40
```

需要取消自启并关闭USB网络时，从Wi-Fi或本地终端执行：

```bash
sudo systemctl disable --now rk-usb-ssh.service
```

不直接在USB会话中用stop／restart作无目的验证；服务当前未启用或首次启用的实际结果、重启恢复均以板端输出为准。
