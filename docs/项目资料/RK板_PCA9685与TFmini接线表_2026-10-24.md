## 1. 本轮依据与编号

SHELL提供的[实物照片IMG_1665.jpeg](../../logs/附件/2026-10-24/IMG_1665.jpeg)可见板卡丝印为`TB-RK3399ProD_33101_V1.2`。低速40pin接口是照片最右侧两列长排针，不是左侧PCIe，也不是MIPI软排线插座。

下文全部为40pin连接器的**物理脚号**，不是GPIO号或Linux总线号。采用[本型号官方表2-4](https://t.rock-chips.com/en/wiki.php?filename=Board_Guide%2FTB-RK3399ProD)的脚号与功能；照片没有足够清晰的1脚角标，不能据此确认“从照片上端或下端数第几排”。接线前须在实物找1脚标记，断电核对GND，再核对对应电源电压。官方网页的表格左右两半是1–20／21–40的分栏，并不是实物左右两列。

本地[Rockchip历史原理图](../验证记录/RK板资料核查_2026-10-21/TB-RK3399ProD_原理图_20181217.pdf)及[GPIO页](../验证记录/RK板资料核查_2026-10-21/TB-RK3399ProD_原理图_P36_GPIO.png)显示J9702为2×20、2.00mm间距，I²C6外侧3.3V，I²C7外侧1.8V。图纸日期2018-12-17／RevV1.0，不冒称已逐网核对V1.2实物。常见2.54mm杜邦插头不能强行套到2.00mm排针，实际间距仍须测量。

## 2. 十根线的对应关系

采用SHELL此前确认的I²C路线：PCA9685与TFmini共用经核对的I²C6，SDA／SCL需分线或使用适配的分线板，不把两个母头强压在同一针上。

| 外设线 | 连接位置 | 说明 |
|---|---|---|
| PCA9685 GND | RK物理5脚GND | 同时与独立舵机电源负极共地 |
| PCA9685 OE | 初次接线：RK物理3脚3.3V | 高电平禁止PWM输出；确认机械／供电后，动作测试改接6脚GND，低电平使能。不得同时接3.3V和GND |
| PCA9685 SCL | RK物理32脚I2C6_CLK | 3.3V I²C时钟 |
| PCA9685 SDA | RK物理34脚I2C6_SDA | SHELL写“SOC”，标准PCA9685接口此线应为SDA；按模块实物丝印核对，不把未知SOC脚直接认作SDA |
| PCA9685 VCC | RK物理1脚3.3V | PCA9685逻辑电源；不接5V，避免常见模块把SDA／SCL也上拉至5V |
| PCA9685 V+ | 独立合格5V舵机电源正极 | 不接RK40pin的5V或12V；初次仅检查逻辑／I²C时可先不接V+，待动作测试再接 |
| TFmini 红线 | RK物理4脚5V，或独立合格5V正极（二选一） | 若按TFmini-S规格，需5V±0.1V、约200mA峰值余量；先核实实际型号、供电能力与带载电压，不将独立5V与RK5V并联 |
| TFmini 白线 | RK物理34脚I2C6_SDA | 条件：确为下述北醒标准线序，且设备已为I²C模式 |
| TFmini 绿线 | RK物理32脚I2C6_CLK | 与上述条件相同；UART模式时此线是TX，不能照I²C接法直接使用 |
| TFmini 黑线 | RK物理36脚GND | 与RK、PCA9685及外部电源负极共地 |

**VCC与V+职责不同：** VCC给控制芯片供电，V+给舵机功率支路供电。舵机电源负极还需要接到公共地；因此“十根线”不是十根都插到RK，也不是完整供电系统只需十根导线。舵机大电流回流直接回到独立电源，不能借RK信号地细线承担。

OE为低有效的输出使能：[NXP PCA9685手册](https://www.nxp.com/docs/en/data-sheet/PCA9685.pdf)及[Adafruit模块引脚说明](https://learn.adafruit.com/16-channel-pwm-servo-driver/pinouts)。Adafruit的默认下拉和VCC上拉结构只证明该厂模块，不保证SHELL手中模块相同；初次接线显式保持OE高，避免仅靠未知板上电阻决定输出状态。

## 3. TFmini颜色与模式的适用条件

[北醒TFmini-S官方手册第4／5节](https://ai.benewake.com/en/resources/technical-documents/tfmini-s-user-manual/)定义：黑GND、红5V、白RXD／SDA、绿TXD／SCL，通信电平3.3V。**这套颜色表以对应型号、原装线序或逐根导通核验为前提**；当前照片只含RK，没有TFmini铭牌及PCA9685模块，不能仅凭红白绿黑确认具体型号，也不能保证新购转接线颜色与传感器原线一一对应。

SHELL此前转述学长确认走I²C；本轮沿用该方向，但尚未读取TFmini当前工作模式。TFmini-S的默认UART与I²C不是通过把白绿线换到SDA／SCL就自动切换，需要按实际型号协议确认或配置。原始TFmini、TFmini-S、TFmini Plus不能混用未核实的切换指令。

当前源码中TFmini默认地址0x10、PCA9685默认0x40，二者候选地址不冲突，但不是本次实物扫描结果。原Nano使用的`/dev/i2c-0`与`/dev/i2c-1`不能直接套到RK；需据当前设备树确认I²C6对应的Linux设备，再配置独立检查入口。本轮只整理接法，不扫描未知总线或启动舵机节点。

**本轮已完成软件映射核对：** `/sys/class/i2c-dev/i2c-6/device/of_node`对应`i2c@ff150000`；pinctrl显示gpio2-9／gpio2-10由`ff150000.i2c`占用、功能`i2c6`、组`i2c6-xfer`。因此本次系统下I²C6对应`/dev/i2c-6`，见[只读映射证据](../验证记录/RK外设修复_2026-10-24/17_I2C总线与引脚复用只读映射.txt)。这证明软件复用和编号，不代替接口空闲电压、传感器模式或实物接线检查。

## 4. 接线前的实物核对

先正常关机并切断RK、TFmini和舵机全部电源，再核对1脚方向、2.00mm连接器及逐线导通；合上供电前核对电源极性与无短路。确认3.3V逻辑和5V功率支路分离、SDA／SCL空闲电平不超过3.3V；不用14／16脚的1.8V I²C7，不用39／40脚的12V_DCIN给这些外设供电。

初次仅给逻辑和测距部分供电，OE保持高，舵机V+先断开；待I²C模式、总线映射及独立供电核对通过，再安排受控动作。当前没有接线、测量、测距或舵机动作验收，不能把本接线表作为已完成的实物验证。

## 5. 2026-10-26重新接线：2×20排针数法

SHELL要求依据原理图重新详细说明接线，并提供[本轮主板照片](../../logs/附件/2026-10-26/codex-clipboard-cf3c017b-2305-4a1a-8ebb-c5109ea3d23b.jpg)。照片可见V1.2丝印、右侧两列排针及亮灯；本轮没有取得断电、插接、实测电压或外设模式的新反馈。

再次视觉核对本地GPIO原理图J9702及官网表2-4，电气脚号与第2节接法相同。**原理图连接器符号不能直接证明实物照片的上／下端与板内／板外列；本轮放大照片后仍无法可靠辨认该排针的1脚标记。** 不把邻近MIPI插座的1／29／30等丝印当成40针排针标记。已请SHELL确认本接口1脚所在端与列；未确认前不指定“照片从上第几排、左／右哪根”。

下面的排数均从已确认的**1／2脚端**朝39／40脚端数，“奇数列／偶数列”不代表照片左右：

| 从1／2脚端数 | 奇数脚一列 | 偶数脚一列 | 本轮用途 |
|---|---|---|---|
| 第1排 | 1：3.3V | 2：5V | 1接PCA逻辑VCC；2可不接 |
| 第2排 | 3：3.3V | 4：5V | 3接PCA的OE保持禁用；4为TFmini候选5V |
| 第3排 | 5：GND | 6：GND | 5接PCA地；6仅供以后受控使能选择 |
| 第16排 | 31：GND | 32：I2C6_SCL | 32分接PCA的SCL与已确认I²C模式TFmini的SCL |
| 第17排 | 33：GPIO1_B2 | 34：I2C6_SDA | 34分接PCA的SDA与已确认I²C模式TFmini的SDA |
| 第18排 | 35：GPIO1_B1 | 36：GND | 36接TFmini地 |
| 第19排 | 37：NC | 38：NC | 不接 |
| 第20排 | 39：12V_DCIN | 40：12V_DCIN | 本轮两脚均不接 |

按原理图，32／34／36三脚沿同一偶数列相邻；SCL32在靠1／2端的一侧，随后SDA34、GND36。与PCA9685共用信号时用匹配间距的分线件，不把两个母头强挤到同一针；若模块有两组同名接口，须断电确认对应脚逐一导通，才可利用第二组转接。

接线顺序：正常关机，断开主板、USB可能供电和舵机等所有供电；确认排针1脚／间距和线序；先共地、PCA逻辑VCC与OE，再接SCL／SDA；TFmini在型号／线序／I²C模式条件满足后连接。首次PCA舵机V+不接、OE接3.3V；独立舵机5V只接V+及公共地，不并联RK5V。OE以后若需改接GND，必须断电换线，不得同时连3.3V与GND。

若1脚丝印无法辨认，下一步取得排针两端及背面焊盘近照，结合断电导通与电源电压实测确认；不能以试插外设判方向。初次量电压应先断电夹好已确认的GND表笔，使用绝缘细探针防止桥接相邻针脚，直流电压档量电压，电阻／蜂鸣档仅在完全断电时使用。方向未确认前暂停外设供电接线。

软件方面，当前开发源码`location.launch`默认bus已为6；10月24日的`/dev/i2c-6`映射证据仍是既有核验，本轮没有SSH复查、扫描或启动任何舵机／飞行节点。实际接线、总线电平、TFmini模式及两模块功能均待本次现场核验。

## 7. V+、UART与两路I2C答疑

SHELL进一步询问为何V+不直接由RK供电、UART含义，以及已有两路I²C为何共用；同时要求查找主板文档。原始PDF、厂家网页和版本边界已整理为[TB-RK3399ProD资料索引](../参考资料/TB-RK3399ProD/README.md)。新取得的原厂位号图J9702角标也与第6节照片方向一致。

**V+供电：** 第2／6节“V+不接RK”是当前工程接法，不是已经测出RK5V不足，也不是PCA模块绝对禁止使用主板5V。VCC给逻辑芯片供电，V+为舵机电源分配支路；舵机启动、换向与负载变化带来电流突变，可能引起共用5V轨压降和噪声。当前缺板载5V可用余量、连接器／线材额定及本机舵机峰值电流证据，因此采用独立合格5V支路。确认这些能力及带载电压／瞬态以后可重新评估主板5V方案，不能用空载5V正常替代。2／4脚是同一5V电源网，不是两份独立电源。厂家DC12V/2A是整板输入规格，不等于排针可额外输出5V/2A。参考[Adafruit引脚说明](https://learn.adafruit.com/16-channel-pwm-servo-driver/pinouts)及[舵机供电说明](https://learn.adafruit.com/adafruit-16-channel-pwm-servo-hat-for-raspberry-pi/powering-servos)；厂商示例不是本机舵机电流实测。

独立5V不要求另一块电池：可由同一电池分出“合格12V稳压→RK”和“合格5V稳压→PCA V+／舵机”两条支路，负极共地，两个5V输出正极不并联。给TFmini使用板载5V也是以供电能力和带载电压核对为条件，不能将它扩大为板载5V已通过所有外设负载验收。

**UART：** 全称Universal Asynchronous Receiver/Transmitter，通用异步收发器；常用TX发送、RX接收，两端TX→对方RX并共地，电源另外连接。不引出共享时钟线，靠一致的波特率和数据帧设置通信，例如双方115200／8N1。它与I²C的SCL／SDA是不同接口；TFmini的白／绿线在两种模式下功能不同。UART描述收发方式，TTL与RS232描述不同的电气接口；本板公开RS232口不能直接接TFmini的3.3V TTL信号。若采用UART，应使用匹配的电平转换或USB转3.3V TTL适配器。参考[Microchip UART说明](https://www.microchip.com/en-us/products/microcontrollers/8-bit-mcus/peripherals/communication-connectivity/uart)与[北醒TFmini-S手册](https://ai.benewake.com/en/resources/technical-documents/tfmini-s-user-manual/)。

**两路I²C：** 确实有I²C6（32脚SCL／34脚SDA）和I²C7（14脚SCL／16脚SDA）。历史原理图显示I²C6已转换到3.3V，I²C7仍为1.8V；V1.2实板空闲电平仍待核对。因此当前把两个3.3V通信外设共接I²C6，省去第二路电平转换。I²C原本支持同一SCL／SDA挂多个不同地址的设备；当前默认PCA0x40、TFmini0x10，由RK按地址逐次访问，不要求一台设备独占一组引脚。默认地址不是实物扫描结果，是否满足实际时序／频率、总线电容和上拉要求仍需联合验证。参考[NXP I²C总线规范](https://www.nxp.com/docs/en/user-guide/UM10204.pdf)。

若需要两路分开，可在I²C7与3.3V外设间使用适用于开漏双向I²C的1.8↔3.3V转换，核对上拉／供电和软件映射后配置；不直接把3.3V模块搬到14／16脚。分开可减少同一总线某设备拉低信号时对另一设备的影响，但本轮未实施接口改接、转换器安装或软件切换。

## 8. SHELL要求分口与I2C7实测准备

SHELL进一步明确不用UART、要求查看当前TFmini源码，倾向两个模块分别用两组I²C，并准备反馈万用表实测。源码已实读确认默认I²C／bus6／0x10，经`TFMiniPro::ReadData()`取数，不会因launch里保留串口参数就打开TX／RX。

分口、供电电压区别、电池输入并联与输出不得混接、未知杜邦线功率边界，以及I²C7物理12／14／16脚的测量顺序见[专门操作说明](RK板分口接线与I2C7测量_2026-10-26.md)。此说明取代此前共用I²C6作为后续目标，未把候选分口记成完成；I²C7电压和接线／转换方案待SHELL实测，源码与板端配置暂未改变。
