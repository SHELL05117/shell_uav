# 给另一台电脑训练助手的独立提示词

以下正文可完整复制给另一台电脑上的Codex或其他能够操作本机文件和终端的助手。把解压后的交接包文件夹作为工作目录；包内有训练方案、原始素材、核查报告、配置示例及校验工具，不依赖原工程目录。这里的“本机”均指接收交接包的训练电脑。

---

你正在协助SHELL完成低空消防无人机的新YOLO视觉模型。请实际检查这台电脑、建立隔离环境、准备数据、训练、评估、导出，并整理可交回的成果。不要只给通用建议或安装命令。SHELL已授权在接收本交接包的这台电脑进行训练；请按可用资源执行，不要向原电脑发起任务。

## 一、先读交接包并核实约束

1. 在当前解压目录中依次读取00_开始阅读.md、01_训练方案.md、config/class_map.json、evidence/README.md和evidence/素材只读核查.json。运行verify_package.py核对交接包的逐文件SHA256；完整数据CRC可用--full-data检查。若聊天中没有提供解压路径，先在当前工作目录定位这些文件，只有确实找不到才向SHELL询问所在目录。
2. 素材位于data/TargetDelection1.1.zip，大小866460635字节，SHA256为6a9d4537ce546ae5bb0c429f565edaf3f0e44c6e0bd628b7faf5a061c9666b41。原包只读；派生数据写新目录，不能覆盖图片或XML原件。
3. 原始材料是180张JPG＋180份Pascal VOC XML，每张标注1个目标，共6类各30张。已有核查没有发现配对／尺寸／框几何错误或完全相同JPEG字节，但没有完成全部像素解码、逐图人工语义审阅和近似连拍分组。请继续这些检查，不把180张直接称为充分的飞行验收数据集。
4. SHELL确定采用YOLO重新训练，完全放弃SSD／MobileNet。不要下载或复用SSD模型、权重、训练脚本、输出契约，也不要以SSD作为必须完成的对照或回退步骤。
5. 目标机为Toybrick TB-RK3399ProD，Ubuntu18.04 ARM64／厂商内核4.4.194／ROS1 Melodic。CPU侧内存约4GB，NPU配套仍未验收。它使用第一代RKNN工具链；不可用RKNN-Toolkit2／Lite2或RK3568／RK3588的结果冒充目标机兼容。
6. 当前电脑只承担训练／导出／转换及材料准备，无需连接RK才能开始电脑侧工作。你没有收到RK私钥或可用远程权限，不猜测原电脑的SSH别名、路径或凭据，也不自动连接无人机或运行任务／舵机。

## 二、环境检查与持续记录

1. 先检测OS、CPU架构、GPU型号／显存、NVIDIA驱动、可用CUDA运行条件、内存／磁盘、Python及现有训练环境。不要假定这台电脑就是RTX3060Ti或固定显存。复用合适的独立环境；新环境放专用目录，别替换系统Python或破坏其他项目。
2. Windows可选择已具备GPU能力的WSL2／容器／独立环境，Linux使用独立环境；选择由实际兼容验证决定。没有可用GPU时先完成核查、数据整理和导出小试，报告训练资源限制，不能把CPU小试说成已完成正式训练，也不自行租用付费云计算。
3. 训练环境与第一代RKNN转换环境分开锁定。训练环境要支持选定YOLO结构，转换环境要匹配旧SDK；不要为迁就一项旧依赖升级／降级整机。
4. 在本工作目录维护TRAINING_STATUS.md和logs/，每阶段记录目标、命令、版本、输入／输出哈希、实际结果、失败和下一步。工程日期按Asia/Shanghai、次日08:00前归前一天；真实运行时间戳另保留。

## 三、模型路线及兼容性检查

1. 首个候选为YOLOv5s-ReLU、6类、640输入，之后才比较v5n-ReLU／其他尺寸。确认源码实际激活函数为ReLU，不能仅改名称；不要擅自换成YOLOv8／YOLO11或训练后临时替换SiLU激活。
2. 先检查包内config/upstream_sources.json列出的固定版本官方资料。首个目标是RK3399Pro专属示例及可验证的六类导出链。原官方演示是80类，必须把六类头、后处理class count、anchors、量化配置同步适配。
3. 在长训练之前，用候选结构和小规模导出验证所选TorchScript或ONNX入口能被第一代RKNN工具链处理，目标明确rk3399pro。普通训练checkpoint不能直接假装TorchScript；ONNX版本和算子支持以实际转换结果为准。
4. 小样本可使用来源可核验的同架构YOLOv5s-ReLU预训练权重，在六类头上重新训练／微调；记录来源、哈希及实际匹配／未匹配层，禁止不加核对地把SiLU权重换激活后直接当等价模型。若缺少匹配权重，记录限制，合理安排小试与数据补充，不隐瞒变化。
5. 没有RK直连时，完成训练电脑上可做的加载、导出、转换与对照；硬件加载、NPU延迟及ROS运行明确标待目标机验收。若旧SDK转换本身失败，保存可复现日志并继续不依赖它的数据／有限训练工作；不要盲目投入长训练后才暴露部署链根本不兼容，也不要用新SDK悄悄替换目标路线。

## 四、数据准备与固定类别

按config/class_map.json固定ID，六类YOLO不添加背景类：

| ID | VOC原类名 | YOLO机器名 | 业务动作 |
|---|---|---|---|
| 0 | 人员 | person_marker | person |
| 1 | 识别项-有毒 | hazard_toxic | hazard |
| 2 | 识别项-易燃 | hazard_flammable | hazard |
| 3 | 识别项-易爆 | hazard_explosive | hazard |
| 4 | 干扰项1 | distractor_1 | 忽略，禁止触发任务 |
| 5 | 干扰项2 | distractor_2 | 忽略，禁止触发任务 |

1. 建立独立派生数据目录，VOC转换YOLO前确认坐标约定；统一为0起始连续边界，再归一化为xc/yc/w/h。不要对所有VOC格式无条件减1，也不要改变类别顺序。
2. 完整解码图片、复查EXIF、检查框和标签，将转换框回画到原图进行审查。当前6类各30张、180个框只是已知结构事实；发现漏标或类别疑点时记录，不篡改原包。
3. 先按采集批次、近似连拍、背景、目标摆放分组，再拆train/val/test。禁止同一连拍或增强副本跨集合。名义60/20/20只是起点，独立采集组优先于凑108/36/36或每类18/6/6；输出split_manifest、分组依据、每类统计与所有文件哈希。
4. 若无法在现有素材上建立可信的独立测试集，仍可进行明确标为试验的首轮训练；报告评估限制及需要补采的真实相机／远距小目标／空场景／多目标／不同背景素材，不能靠随机划分制造高精度。
5. config/data.yaml.example仅为模板。根据本机实际派生数据根目录生成真正的data.yaml，并使用UTF-8保存；模板不是已经转换完成的数据集。

## 五、训练、验证、导出与量化

1. 先做小批量训练／前向／恢复测试，确认图像、标签、六类头、GPU及显存工作正常；根据本机资源确定batch、workers等，不照抄其他机器参数。
2. 正式训练以640、固定种子、合理早停为起点，评估150–300轮上限；这是待测起点，不是必须凑满的轮数。增强只在训练集，强度需人工检查，避免破坏图案语义。保存最优与可恢复checkpoint、完整超参数、训练曲线、环境锁定和实际执行命令。
3. 模型选择依据验证集，冻结测试集不反复调参。报告每类精度／召回、mAP、混淆矩阵、框定位情况；单列两个干扰类误判为业务目标的情况。未经SHELL确定，不编造业务验收阈值。
4. 输出可复现的浮点推理工具和带框示例。导出中间模型、anchors／输出头约定及配置，先与训练框架在相同输入上比较，检查预处理、颜色、letterbox和框坐标还原。
5. 在旧SDK隔离环境使用代表性训练／额外校准数据进行8位非对称量化，最终测试集不得用于校准。比较同一个YOLO的浮点与RKNN量化结果，逐类报告变化；不拿其他硬件的FPS当本板性能。
6. 无法产生RKNN时，如实交付浮点模型／中间导出、日志、失败复现和剩余条件；不得把ONNX或.pt改后缀冒充.rknn。RK实际驱动、代理、固件、NPU连接方式尚待目标机确认，不生成或刷写未经匹配的固件。

## 六、需要交回的成果

- README_交回说明.md：实际完成项、未完成项、可复现命令、下一步；清楚区分训练完成／转换完成／目标机验收。
- 环境和版本：训练／转换仓库URL与commit、真实配置／激活函数、依赖锁定、GPU与驱动记录。

- 模型：best checkpoint、可恢复checkpoint获取方式、验证过的中间导出、anchors及对应RKNN（如果转换成功），所有文件SHA256。
