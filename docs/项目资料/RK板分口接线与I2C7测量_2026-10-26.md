## 1. SHELL当前要求与实施边界

2026-10-26晚间，SHELL明确希望PCA9685与TFmini分别使用两个I²C口，不再按共用I²C6作为后续目标；先取得I²C7实测电压。候选分配为PCA9685→I²C6（32／34脚），TFmini→I²C7（14／16脚），待电平和接口路径核对后确定是否需要双向电平转换。本轮只核对源码并给出测量步骤，未改源码／launch参数、未接线、未SSH或运行硬件测试。

此前两个模块共享SCL／SDA是并接I²C总线，不是串联供电。分口要求不改变TFmini的5V供电、PCA逻辑VCC与舵机V+分开的职责；电平转换与供电必须分别判断。

## 2. 两个降压模块的并联与杜邦线

同一电池同时供两个降压模块时，合理拓扑是**输入并联**：电池正极分别到两模块IN+，负极分别到IN−。5V OUT+只去5V负载，12V OUT+只去12V负载，两个不同电压的输出正极不互连。若电池为普通4S，5V模块的输入范围也必须覆盖16.8V满电及实际工作范围，不能只看它标称输出5V。

普通杜邦线的线径、导体材质、端子接触和额定电流未知，不能据“能插上／空载有电压”认定可作为电池分电或舵机功率线。当前不以未知杜邦跳线替代电池到两模块的正式供电线，也不捆多根未知杜邦线推定足够。后续应使用匹配负载电流、可靠固定与绝缘的分线线束／端子和导线；不在本轮给一个未经核实的通用安培数。

当前可先用原装12V适配器完成主板空闲电平测量，PCA舵机V+保持断开，不需要为测量临时搭建电池分电支路。此安排不表示板载5V已被证明不足。

## 3. 当前源码实际调用TFmini的方法

- [location.launch](../../src/location/launch/location.launch)第16行默认`tf_mini_type=i2c`，第27行`bus=6`，第28行`address=16`，即0x10。
- [location_with_ftmini.cpp](../../src/location/src/location_with_ftmini.cpp)第67–74行进入I²C分支，构造`TFMiniPro(address,bus)`，建立0.05秒定时器；第138–142行通过`i2c_->ReadData()`取数。UART是第76行开始的独立可选分支，默认I²C配置不打开它。
- [i2c.cpp](../../src/location/src/i2c.cpp)第13–23行打开`/dev/i2c-<bus>`，使用`I2C_SLAVE`设置目标地址。
- [tf_mini_i2c.cpp](../../src/location/src/tf_mini_i2c.cpp)第110–125行发送I²C厘米格式请求、读取数据并换算成米。

因此本次TFmini的通信接线是SCL／SDA，不接UART TX／RX；launch保留串口参数不等于默认使用串口。软件选择I²C也不代替对传感器实物模式／线序的确认。将来分配到I²C7时，需要在硬件适配和Linux映射确认后改相应bus参数，无需为分口改成UART。

[10月24日只读映射证据](../验证记录/RK外设修复_2026-10-24/17_I2C总线与引脚复用只读映射.txt)同时列出`/dev/i2c-6→ff150000`及`/dev/i2c-7→ff160000`和相应pinctrl占用；它是既有系统证据，本轮没有重新连接板端验证。

## 4. 供电电压与通信电平

| 对象 | 电源 | SDA／SCL通信要求 |
|---|---|---|
| TFmini | 沿用此前确认的5V供电；不是改成3.3V。TFmini-S官方示例为5V±0.1V | 按对应型号的3.3V通信接口匹配，不把5V供电理解成信号也用5V |
| PCA9685逻辑VCC | 本项目与RK3.3V直接通信时用3.3V；芯片VDD额定2.3–5.5V，模块外围另核对 | 常见模块SCL／SDA上拉到VCC，因此VCC设5V可能把总线拉到5V；PCA在3.3V供电时也不能保证把1.8V认作高电平 |
| PCA9685舵机V+ | 本机此前确认的5V舵机功率支路，初次逻辑测量先不接 | 不决定SDA／SCL电平 |

依据：[北醒TFmini-S手册](https://en.benewake.com/uploadfiles/2023/03/20230331102952719.pdf)、[NXP PCA9685数据手册](https://www.nxp.com/docs/en/data-sheet/PCA9685.pdf)及[Adafruit引脚说明](https://learn.adafruit.com/16-channel-pwm-servo-driver/pinouts)。NXP规定PCA9685的SCL／SDA高电平门限最小为0.7×VDD：VDD=3.3V时是2.31V，因此不能直接以1.8V总线作为可靠高电平；VCC也不能降至1.8V低于芯片供电额定下限。

历史原理图I²C6外侧已转3.3V，I²C7是1.8V直接引出；若实板I²C7确为1.8V，需适合开漏双向I²C的1.8↔3.3V转换。不能通过把模块电源改成1.8V或把1.8V接口直接上拉到3.3V来替代。

## 5. 找到要测的三个针脚

按SHELL照片方向：上方为DC12V插座，下方为WiFi模块；靠MIPI／散热器为内侧偶数列，靠PCB板边为外侧奇数列。以排针最下端为第1排，每排包含内外两根，不按单根针尖累计排数。

| 功能 | 物理脚 | 位置 |
|---|---|---|
| 测量公共地 | 12脚GND | 内侧列，从下第6排；等价从上第15排 |
| I²C7 SCL | 14脚 | 内侧列，从下第7排；等价从上第14排 |
| I²C7 SDA | 16脚 | 内侧列，从下第8排；等价从上第13排 |
| 可选参考3.3V | 1脚 | 外侧列，最下排、白色三角对应处 |

因此12／14／16在同一内侧列，由下向上连续为GND、SCL、SDA。针尖可能弯斜，应按排针根部的行列定位。

## 6. 万用表操作顺序

1. 正常关机并断开全部供电。将TFmini和PCA9685从待测排针断开，舵机V+不供电；本次只测主板自身空闲电平，避免外设上拉或输出影响结果。
2. 黑表笔插COM，红表笔插电压用V／Ω孔，不插独立A／mA／10A孔。选择直流电压V DC／V⎓；手动表用20V档，自动表选直流V。通电时不使用电阻、蜂鸣或电流档测这两个信号。
3. 在断电状态固定黑表笔到已确认的12脚GND。优先使用匹配2.00mm的引出线／绝缘夹；没有可靠固定方式时，不用粗裸表笔同时挤入相邻针脚。红表笔用绝缘细探针或套管，仅露出足够接触的短针尖，防止跨接相邻针。
4. 使用原装12V适配器给RK正常上电并等系统启动。不要运行定位、舵机或I²C扫描程序，保持待测总线空闲；测量期间不插拔外设。
5. 可先用红表笔量1脚对12脚GND，预期约3.3V，作为档位／地参考核对；若明显不符，先停下核对位置和仪表。
6. 黑表笔保持12脚GND不动，红表笔接14脚SCL，稳定数秒后记录电压及是否跳动。
7. 红表笔离开14脚后，再接16脚SDA，同样记录。每次只接触一根信号针，不把表笔接在SCL与SDA之间测差分电压。
8. 测完先移开红表笔，正常关机并断电，再移除固定的黑表笔／测量引线；外设改接只在断电后进行。

仪表档位／插孔依据[Fluke直流电压测量步骤](https://www.fluke.com/en-us/learn/blog/digital-multimeters/how-to-measure-dc-voltage-with-a-digital-multimeter)，本项目补充了2mm排针的具体位置与防桥接措施。

## 8. 1.8V反馈后的试用选择与板载5V候选

**[SHELL实测反馈]** I²C7确为1.8V；没有提供14／16各自读数、是否空载和仪表档位，因此只按该文字反馈记录，不补成两个1.800V测量值。**[SHELL转述]** 学长表示接1.8V逻辑没有问题；这记录为建议来源，不写成具体型号的电气兼容证据。

**[SHELL选择]** 优先TFmini→I²C7、PCA→I²C6；如果分口不能满足要求，再考虑共用6。PCA V+改由RK2脚5V供电，替代此前本轮候选的独立5V支路；SHELL仅有细杜邦线、12V模块在机内用302胶固定且难以取出重焊，暂不要求拆胶、改焊电池支路。此处是试用决策，未证明板载5V及线束已满足舵机负载。

### 8.1 必须分开核对的两类电平问题

1. TFmini能否可靠识别1.8V高电平，取决于实物型号的输入门限；已有TFmini-S手册只标通信LVTTL3.3V，不能据此给未知型号作1.8V保证。
2. TFmini自身若有到3.3V的SDA／SCL上拉，或信号实际为推挽输出，直接连接可能抬高RK1.8V总线。新查[RK芯片手册第60页](../验证记录/RK板接口电平依据_2026-10-26/RK3399Pro_Datasheet_P60_1V8_GPIO.png)中，1.8V数字GPIO的输入高电平规格范围为1.17–2.1V，不能默认3.3V容忍。该范围是DC规格，不误称为绝对最大额定值。

因此，先仅接TFmini已核对的5V／GND，让白／绿信号线完全离开RK及其他模块，再用直流电压档分别量白对黑、绿对黑并记录。若有约3.3V，不直接接到RK1.8V信号脚，应核对上拉／驱动路径，选择已匹配电平的接口方案。若为0V或悬浮，也不能仅据此判定可直连；还需确认模式、开漏与输入门限条件。不通过把外设接上、再观察RK引脚是否升到3.3V来排查。

### 8.2 SHELL选择的候选针脚

| 接口 | RK针脚与照片位置 | 初次检查边界 |
|---|---|---|
| PCA VCC | 1脚3.3V，外侧从下第1排 | 保持逻辑3.3V |
| PCA OE | 3脚3.3V，外侧从下第2排 | 保持输出禁用 |
| PCA GND | 5脚GND，外侧从下第3排 | 信号与电源回流接点，接线／端子额定仍须核对 |
| PCA SCL／SDA | 32／34脚，内侧从上第5／4排 | 继续用I²C6 |
| PCA V+ | **2脚5V，内侧最下排** | 改为板载5V候选，先拔掉PCA上的全部舵机插头再检查 |
| TFmini红／黑 | 4脚5V／36脚GND | 按既定核对线序供电；先不接白绿信号 |
| TFmini绿SCL／白SDA | 拟14／16脚，内侧从下第7／8排 | 只是拟接点，须先通过8.1电气核对，不作为1.8V直连已获验证的接线说明 |

PCA舵机插头全部拔下、OE高时，先检查V+对GND及RK5V，确认接法无误；这只验证空载电源路径。后续任何单只空载动作均需先核对线束／电源能力并另行受控开展，不直接两只带载或运行导航任务。如出现5V明显下降、板重启、接头／线发热或测距掉线，应停止对应测试；这些现象不能反过来当作正常用法。无异常的万用表平均值也不能证明没有瞬时压降。细杜邦线＋板载5V尚不能记为已验收的飞行供电方案。

### 8.3 软件与后续结果

当前源码默认TFmini bus仍为6，未修改或部署。现有独立`tfmini_test`工具可指定bus7和地址十进制16，不必先改生产默认配置；实际运行须等实物连接和电气条件确认，不能用包含定位／飞控等链路的默认launch替代独立测距检查。本轮未运行工具或发送舵机动作。

只有取得接口电平／门限依据、独立距离正确性与连续通信结果，再叠加舵机供电负载验证后，才能决定是否保留分口与板载供电；仅扫描到地址、读到几帧或舵机空载转动不能跨级写成长期或飞行验收。实际接线进度询问后，SHELL回复两模块均尚未连接；当前先做TFmini独立供电信号电位核对，结果待反馈。

结合RK1.8V GPIO规格，当前没有证据支持把这两根信号直接接到I²C7；建议沿SHELL此前提出的后备方向研究共用I²C6，而不是先接1.8V接口再观察是否可读。若坚持分口，仍需相应的电平匹配方案或可证明双向兼容的电路依据。

为降低分线难度，核对实际PCA9685是否在两端均有**已焊好的同名SCL／SDA插针**。Adafruit原厂说明其两端控制接口相同，但不能直接证明SHELL模块同构；当前项目可见文字和主板照片不足以辨认这块PCA两端实际接口。下一步需其正面全图，拍到两端接口及丝印，或由SHELL在PCA完全断电、断开其他连接后核对两侧SCL↔SCL、SDA↔SDA分别为接近表笔短接值的低阻导通；不要把SCL与SDA互相短接作检查。

仅在上述实物确认成立时，候选接法为：

```text
RK32 SCL → PCA第一组SCL ──板内同名连接── PCA第二组SCL → TF绿线
RK34 SDA → PCA第一组SDA ──板内同名连接── PCA第二组SDA → TF白线
```

这是在PCA的电路板上转接同一条I²C总线，不是信号经过PCA处理后再发送。TF红线继续使用已核对RK4脚5V、黑线RK36脚GND；不要把TF5V红线改接PCA3.3V的VCC。PCA逻辑VCC仍1脚3.3V、OE3脚高禁用、GND5脚；V+仍为SHELL选择的RK2脚5V候选，所有舵机插头先拔下。若PCA只有未焊焊盘或只有一组接口，不强插／挤压杜邦头，需要再定可靠分线方法。

## 10. IMG_1738实物：无排针时的焊线候选

### 10.2 无排针的做法

确认同名导通后，可将TF绿／白信号线靠PCA的一端直接焊到相应上端孔。若该端为杜邦母头，需要去掉该端接头、剥少量线皮并预上锡；保留TF传感器端连接器。这样TF线束与PCA形成焊接连接，之后要拆开需退焊；不把母头或未焊公针塞入空孔作接触。

先在正面标清SCL／SDA孔，再根据标记翻到背面焊，避免翻面后左右镜像导致认错孔。预镀锡后让导线穿入孔，用适合电子焊接的焊锡／助焊剂，使锡同时润湿焊盘与导线，避免反复长时间加热。剪短多余裸露线尾，检查无锡桥或散落锡珠，再做绝缘和线束拉力固定，不能让线束直接牵拉焊盘。

焊后仍在完全断电状态，确认TF绿线↔下端SCL、TF白线↔下端SDA分别低阻导通，SCL与SDA之间无持续低阻短路，并检查相邻焊孔未桥连。没有焊接或导通实测反馈前，不记为已完成。
