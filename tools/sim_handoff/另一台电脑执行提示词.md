# 给接收端agent的独立任务提示词

你正在帮助SHELL在另一台已配置Docker和WSL的Windows电脑建立低空消防无人机的全链软件仿真。请先读取解压包`handoff/README_先读.md`、`BASELINE.json`及`project/AGENTS.md`，按实际路径工作。本提示词替代旧异机提示词中SSD、Nano和“尚无仿真场景”的过时假设。旧文档与源码作为历史和证据保留。

## 已授权目标与边界

- 在这台电脑核查环境、安装所需依赖、建立隔离可复现环境、编译项目，并分阶段开展PX4 SITL／Gazebo与ROS全链仿真；可对独立副本新增YOLO适配、仿真launch及必要修复，记录并提交，不反复要求SHELL确认常规可逆操作。
- 不连接真实RK／PX4／舵机，不运行硬件服务，不刷机，不以仿真通过替代实物或飞行验收；不重训或切回SSD／MobileNet，不上传到GitHub或发送消息给其他agent。
- 保留已有WSL发行版、Docker镜像／卷和数据；不重装Docker、不清空工作环境、不执行全局prune，不改Windows分区。修改WSL资源或重启前先说明影响，确保已有工作可保存。
- 工程按SHELL习惯：次日08:00前归前一天。真实执行时间另记；接收电脑从实际工程日期记录，不套用发送端日期。新日志应回传给原项目。

## 阶段0：包校验与机器盘点

1. 运行`handoff/verify_package.py`核对清单；保存环境信息。Windows用`inspect_host.ps1`，WSL／容器内用`inspect_linux.sh`，也可直接执行等效只读命令。不要收集凭据、Wi-Fi配置或私钥。
2. 读取CPU／内存／可用磁盘、Windows／WSL版本、Docker Desktop后端／Server架构、已有容器和卷、是否有GPU与OpenGL渲染能力。不要将另一台电脑的RTX3060Ti／16GB假设当作实测。
3. 已有ROS／Gazebo／PX4则优先复用兼容环境。若尚无用户态，先评估Ubuntu18.04／Melodic／Classic9／PX4 v1.13.3；已有Noetic时评估Ubuntu20.04／Noetic／Classic11与同版PX4源码的兼容性。列明最终选择和理由，锁定镜像digest、PX4 commit及子模块，不追随main。
4. 独立WSL Ubuntu不是Docker Desktop运行命令的必需条件，但本项目GUI和Linux工作流可能用到WSLg／集成发行版。不要另装第二个冲突Docker daemon。

## 阶段1：可复现编译环境

- 参考`handoff/环境与外部依赖.md`、apt清单及Dockerfile模板。旧软件源失效时保留原报错，核对官方签名／快照／匹配二进制包或锁定源码，不关闭签名检查来冒充解决。
- 源码在容器Linux卷或WSL Linux文件系统内构建，不复用发送端build／devel；Windows可保存输入快照和导出的证据。
- 起步编译并行度2，读取实际资源再调整。完整8包构建，记录C++目标和消息生成覆盖；Jetson专用视觉目标跳过要明确写出，不能称为视觉迁移完成。
- 运行与改动相关的已有gtest和ROS消息／回环测试，避免硬件脚本。Python推理核验工具使用Python3.10+；Melodic原生Python2.7 ROS／cv_bridge不能直接与新Python3虚拟环境混用，选独立进程或明确验证过的桥接方案。

## 阶段2：基础SITL与传感器

- 单独验证PX4＋MAVROS、仿真时钟、基本控制，再加入项目室内场地／Iris／传感器架。先关任务：已核对环境后可参考`ROS_DISTRO=melodic bash src/gc_2026_sim/scripts/start_px4_slam.sh start_mission:=false auto_start:=false`；Noetic须改对应值。命令不是本包已运行通过的保证。
- 渲染先看实际OpenGL renderer和Gazebo日志，再看相机输出，不以nvidia-smi代替。GUI、相机、雷达、`/clock`、MAVROS分别记录频率／停顿／RTF。
- 使用一致的use_sim_time；验证map→odom→base_link→laser_link，以及相机TF和高度来源。区分Gazebo真值辅助与Cartographer估计，记录谁给控制提供了位置，不能用真值飞完一圈就宣称独立SLAM验收。
